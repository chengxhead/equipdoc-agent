# EquipDoc-Agent 3～5 分钟面试演示 Runbook

> 目标：用一条稳定、可复述、不会越界的演示主线，证明项目不仅有页面，还具备受约束规划、工具审核、证据回答、安全降级和可复现评测。

## 1. 先选对演示模式

| 模式 | 现场用途 | 能证明什么 | 不能声称什么 |
|---|---|---|---|
| 本地 Demo | 默认主方案，稳定且不依赖 GPU | Gradio 交互、知识检索、Approve/Reject、路径脱敏、安全边界、固定案例报告 | 不能说知识回答来自 Qwen；不能说故障类型来自真实 CNN 推理 |
| AutoDL Full Agentic | GPU 和端口映射稳定时使用 | 真实 Qwen 规划、结构化证据回答、真实 CNN 工具链和多轮记忆 | 仍不能声称人工正确率或工业诊断准确率 100% |

推荐策略：面试现场以本地 Demo 保证流程稳定，用正式 AutoDL 结果证明 Full 链路；只有在面试前已经完成一次 Full 页面预演时，才把 AutoDL 作为主现场。

## 2. 本地演示前检查

在 PowerShell 中执行：

```powershell
cd <equipdoc-agent-portfolio 仓库目录>
.\.venv\Scripts\Activate.ps1
python -m equipdoc_agent.health --strict
python scripts/demo_smoke.py
python app_gradio.py
```

预期：

- 健康检查 `ready=true`；
- Smoke 输出 `mode=demo_fixture`；
- 页面监听 `http://127.0.0.1:7860`；
- 页面顶部明确显示“Demo 模式”；
- 浏览器中不要打开 `.env`、AutoDL 路径、模型目录或无关终端。

如果 7860 被占用，应用会自动尝试后续端口，以终端实际地址为准。

## 3. 推荐的 4 分钟本地演示主线

### 0:00～0:25：一句话介绍

页面保持在首页，直接说：

> 这是一个面向机电设备运维的可审核 Agent。大模型负责理解任务和组织证据，确定性策略负责工具权限、参数校验和高风险边界，轴承诊断执行前必须经过人工审核。

不要一开始讲模型参数或测试数量，先说业务问题和系统约束。

### 0:25～1:05：知识问答与证据

保持“使用仓库内置演示信号”为勾选状态，输入：

```text
轴承外圈出现局部点蚀时，包络谱通常有什么表现，现场应怎样交叉确认？
```

点击“提交”。预期：

- 状态为“已完成”；
- 不出现诊断审核；
- 返回外圈故障相关知识片段和 `doc_id#chunk_id`；
- 本地 Demo 会明确说明不调用 7B 模型。

讲解：

> 即使页面带着样例信号，知识问题也不会误触发 CNN。这里是无模型 Demo，所以展示的是可回查的词法检索片段；真实 Qwen 的结构化证据回答已经在 AutoDL 冻结集上重复验证。

### 1:05～2:20：诊断审核与报告

输入：

```text
请诊断这段轴承振动信号，并给出判断依据和处理建议。
```

点击“提交”。预期：

- 状态为“等待人工审核”；
- Approve 和 Reject 变为可用；
- 审核载荷只显示 `signal_file: test_signal.npy`，不显示绝对路径。

先停留 5～10 秒，讲解：

> 知识检索是只读工具，可以直接执行；轴承分类会影响维修判断，所以必须经过人工审核。模型也不能自己构造服务器路径，真实路径由系统注入，审核页只显示脱敏文件名。

点击 Approve。预期报告包含：

- “固定演示案例”醒目标识；
- 故障类型和信号摘要；
- 检索证据；
- 处理建议；
- 不推断精确寿命等已知边界。

讲解：

> Demo 标签不能删除，避免把固定案例误解为真实模型推理。Full 模式会调用真实 CNN，但维修决策仍需要现场点检和历史趋势。

### 2:20～3:05：高风险边界

输入：

```text
只根据一次振动采样，精确告诉我这个轴承还能运行多少天。
```

点击“提交”。预期：

- 不进入诊断审核；
- 直接进入 `remaining_life` 安全边界；
- 拒绝精确天数；
- 说明需要长期趋势、载荷谱和退化模型。

讲解：

> 安全策略优先于工具路由。即使当前存在信号，也不能用单段采样推断精确剩余寿命。

### 3:05～4:00：工程结果与收尾

不用切换页面，口头总结：

> 已归档的 P2.2 Fix 3 评测快照在冻结 56-case、64-turn 正式集上为 64/64，p95 从 P2.1 的 16.758 秒降到 9.926 秒，38 个证据回答全部进入结构化路径。当前 Live 规划热修复代码的复测是 63/64，不能混用旧快照背书。两个指定页面问题已经连续复验，不再显示规划降级。

然后用一句话收尾：

> 我重点解决的不是让模型自由调用更多工具，而是让模型、工具和确定性安全策略各自只承担适合自己的职责，并把失败路径也纳入评测。

## 4. 30 秒可选分支

### Reject 分支

重新提交诊断请求，在审核页点击 Reject。预期返回：

```text
已根据人工审核取消本次诊断工具调用。
```

适合面试官追问“人工审核是不是真的能阻止执行”时演示。

### 缺少信号分支

取消勾选样例信号，输入：

```text
请分析这段振动信号有没有轴承故障。
```

预期提示上传 `.npy` 或重新勾选样例，不应继承上一轮信号。

适合面试官追问多轮状态或信息不足处理时演示。

## 5. AutoDL Full 演示主线

Full 页面仍使用上述三个核心问题，但讲解口径不同：

1. 知识问题应展示 `structured_evidence_answer`，而不是本地 Demo 的词法片段；
2. 诊断审核通过后调用真实 CNN 权重；
3. 同一线程可继续追问“为什么置信度不能单独作为维修决策依据”；
4. 剩余寿命问题仍必须由安全策略拒绝。

2026-08-01 的 Full 页面已走通上述主线；但当前 Live 热修复代码的正式回归为63/64。面试中若引用64/64，必须明确它属于已归档 Fix 3 评测快照，而不是当前 Live 代码。

面试前必须确认：

- Qwen `/v1/models` 和探针返回 Ready；
- Gradio、Qwen 和 CNN 使用的是同一份最新代码；
- AutoDL 端口映射可从面试设备访问；
- 至少完整走通一次知识问答、Approve、Reject 和安全边界；
- 准备本地 Demo 作为断网或实例异常时的立即降级方案。

## 6. 现场故障处理

| 现象 | 现场处理 |
|---|---|
| 7860 被占用 | 使用终端显示的新端口，不在现场排查旧进程 |
| Full Qwen 超时 | 立刻切回本地 Demo，引用已保存的三轮 Demo 和 64-turn 证据 |
| 页面停在审核状态 | 明确选择 Approve 或 Reject，不直接重复提交 |
| 知识回答进入安全拒绝 | 检查问题是否包含精确寿命、远程控制等高风险要求 |
| 输出与预期不一致 | 不现场改 Prompt；切到固定问题并在面试后复盘 |
| 面试官要求开放提问 | 先说明知识库和工具范围，范围外问题允许澄清或拒绝 |

- [ ] 准备 Full 失败时切回本地 Demo 的话术。
