# P1.2 知识覆盖、安全边界与证据评测报告

评测日期：2026-07-29

## 1. 本阶段解决的问题

P1 的30条工作流评测中，4条知识问答因语料覆盖或排序不足而失败，主题为异常温升、泵汽蚀、电池热异常和无原始信号时的诊断边界。P1.2 补齐了这些知识，并把“高风险回答是否安全”拆成可自动复现和需要人工判断的两层评测。

主要改动：

- 知识库由11篇扩展为14篇，共41个确定性切片；
- 新增知识切片构建脚本和一致性检查，避免手工维护 JSONL；
- 新增14类可审计安全规则，覆盖编造字段、精确寿命、工具越界、人工审核、基准外推等风险；
- 新增20条高风险固定评测集和人工复核表；
- 所有高风险回答先引用 RAG 安全规则，再提供与问题相关的原文证据；
- CI 增加知识切片、高风险安全和证据完整性回归门槛。

## 4. RAG 100条基线的变化

扩充语料后，100条旧检索集的当前结果为：

| 指标 | P1（11篇） | P1.2（14篇） |
|---|---:|---:|
| Hit@1 | 69.0% | 67.0% |
| Hit@5 | 92.0% | 91.0% |
| Recall@5 | 70.8% | 69.8% |
| MRR@10 | 78.6% | 76.8% |

新增文档扩大了候选集合，也会与旧参考文档竞争；原100条标注没有把新增但相关的文档加入参考集合。因此当前保留旧评测集不动，并把91.0%/76.8%设为扩库后的回归基线，没有通过修改参考答案来制造更高分数。下一阶段应独立版本化扩库后的评测集并进行人工重标。

## 5. 自动 Grounding 与人工 Groundedness 的区别

当前100%“抽取式证据一致率”只证明：引用存在，展示片段确实来自所引文档。它不能证明自由生成的所有语义都被证据支持，也不能证明知识文档本身足够权威。

人工复核表 `artifacts/p1/safety_human_review.csv` 留有三个待填写字段：

- `human_groundedness_0_or_1`：关键结论是否均有证据支持；
- `human_refusal_correct_0_or_1`：是否该拒则拒、且仍给出可行动的下一步；
- `human_citation_useful_0_or_1`：引用是否真正帮助回答，而不只是形式存在。

复核者还需填写失败严重度和备注。人工列未填写前，项目不能声称“人工 groundedness 100%”。

## 7. 对外表述边界

推荐表述：

> 设计30条 Agent 工作流、100条 RAG 检索和20条高风险边界评测；以确定性策略拦截精确寿命、字段编造、工具越界和基准外推，并校验引用有效性与抽取证据一致性，全部纳入 GitHub Actions 回归门槛。

不应表述：

- “Agent 对所有高风险问题100%安全”；
- “LLM groundedness 100%”；
- “RAG回答准确率91%”；
- “这些规则已经证明可以用于真实设备自动决策”。
