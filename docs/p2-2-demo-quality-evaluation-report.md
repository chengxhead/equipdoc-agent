# P2.2 面试 Demo 质量与稳定性评估报告

> 状态：截至 2026-08-01，AutoDL RTX 4090 上的 2-case 预检、13-turn Demo 三次重复运行和冻结 56-case / 64-turn 正式自动回归均已完成。Demo 人工复核工作簿已生成，但当前仍为 0/13。

## 1. 目标与结论

P2.2 针对 P2.1 暴露的两个主要问题进行整改：证据回答全部落入粗粒度抽取式 fallback，以及模型重试带来的无效延迟。整改没有放宽既有意图、工具、审核、隐私、引用、grounded guard、记忆和关键词合同。

最终结果为：

- 冻结的 13-turn Demo 连续运行 3 次，自动合同均为 13/13；
- 冻结的 56-case / 64-turn 正式集最终自动合同为 64/64；
- 38 个需要知识证据的正式 turn 均进入 `structured_evidence_answer`，答案层 `safe_fallback` 为 0；
- 相比 P2.1 最终基线，正式集平均 / p50 / p95 延迟分别下降 31.75% / 31.05% / 40.77%；
- 自动结果不能替代事实正确性、回答完整性、引用有用性和安全适当性的人工判断。

## 3. 整改内容

### 3.1 证据选择与回答组织

- 把多子问题拆成可验证的证据槽位，优先覆盖机理、信号特征、现场复核和安全边界；
- 对明确设备或故障对象设置聚焦优先级，减少跨设备或相邻故障证据漂移；
- 同一文档在 top 5 中最多保留 3 个互补切片，单个引用最多选择 3 个互补句；
- 对现场复核问题优先包含“复核、巡检、检查、确认、验证、排查”等动作证据；
- 使用确定性的结构化证据渲染器组织最终回答，并保留可回查的 `doc_id#chunk_id` 引用；
- 增加规划、证据选择、槽位缺失、综合校验和生成路径诊断字段，便于定位失败而不是只看总通过率。

### 3.2 延迟与无效重试

当模型首个综合草稿没有引用或明显不满足 grounded 约束时，不再进行同类无效综合重试，直接使用已经通过槽位检查的结构化证据答案。该策略减少了平均 LLM 调用次数，并保持最终自动合同不变。

P2.2 的主要收益来自回答层结构化和无效重试削减。规划器接受率仅从 48.1% 提升到 50.0%，不能把本轮结果描述为规划能力已解决。

## 8. 人工复核与未解决问题

[`demo_human_review.xlsx`](../artifacts/p2_2/demo_human_review.xlsx) 已预填 Run 3 的 13 个 turn，并为事实正确、回答完整、引用有用、安全适当和总体结论保留空白人工栏。当前人工复核为 0/13，因此不能报告人工正确率、人工 groundedness、引用有用率或安全适当率。

还存在以下限制：

1. 52 个规划 turn 中仍有 26 个使用确定性 fallback，规划稳定性只有 50.0%；
2. 38 个证据回答均由确定性的 `structured_evidence_answer` 交付，证明最终答案可控，但不证明 Qwen 自由综合已经稳定；真实草稿仍经常因缺少可验证引用而未被采用；
3. 正式 `knowledge_qa` 分组 p50 为 7.055 秒，仍高于 6 秒目标；p95 为 9.778 秒，低于 12 秒目标；
4. 当前知识库是项目知识笔记，不是带版本的权威设备手册或标准；引用可回查不等于事实已由权威来源确认；
5. P2.1 正式人工复核仍为 0/64；
6. CNN 仍缺少按原始文件和工况 Group Split 的可信准确率评估，不能从本轮 Agent 回归推导工业诊断准确率。

## 8.1 Full Gradio 规划热修复（报告后更新）

Full 页面复验发现两个指定演示问题会显示规划降级：知识题偶发不返回 JSON，诊断题连续把系统资源 `signal_file` 写成未知步骤依赖。热修复强化了最后一条 JSON 指令，并只对信号工具的系统资源依赖进行安全归一化和审计；其他未知依赖继续拒绝。130项单元测试与 Ruff 均通过，指定知识题和诊断题连续3轮共6次均未进入 `deterministic_fallback`，真实页面也不再显示规划降级。

由于修改影响全局规划 Prompt，使用热修复代码重新运行冻结合同：

| 数据集 | 自动合同 | 平均 / p50 / p95（秒） | 平均LLM调用 | 规划路径 |
|---|---:|---:|---:|---|
| 13-turn Demo | 13/13 | 5.333 / 6.031 / 9.851 | 1.538 | 首轮7、重试2、确定性fallback 2、无规划2 |
| 64-turn正式集 | 63/64 | 4.569 / 5.442 / 8.954 | 1.563 | 首轮31、重试14、确定性fallback 7、无规划12 |

正式集的意图、工具覆盖、白名单、审核、隐私、澄清、记忆和关键词仍为100%，但一个 `diagnosis` turn 没有进入合格证据路径，导致引用有效率和 Grounded Guard 均为37/38（97.37%）。按当前收口决定，该失败未继续定位。因此：

- 第6至第7节的64/64仍是已归档 Fix 3 评测快照；
- 当前包含规划热修复的代码版本只能报告63/64；
- 页面指定演示流程已通过，不等于全量正式合同通过；
- 不得使用旧64/64证据为当前热修复代码背书。
