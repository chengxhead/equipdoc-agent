## 3. 验证过程中发现并修复的问题

### 3.1 知识问题被样例信号误导为诊断

旧 Demo 策略把“轴承”“故障”“状态”等领域词本身当作诊断意图。页面默认携带样例信号时，纯知识问题会错误进入 CNN 审核。

修复后只在以下情况进入诊断：

- 明确指向当前、上传或这段信号的诊断、分析、判断、分类请求；
- 明确命令式要求执行诊断；
- 明确要求输出故障类型、概率、置信度或诊断结论。

“为什么、什么、哪些、通常、机理、区别、表现”等自包含知识问题不会因为页面携带样例信号而改变路由。

### 3.2 取消样例后仍继承上一轮信号

Gradio 在同一 `thread_id` 下保留 LangGraph 状态。旧提交在没有新信号时省略 `signal_path` 字段，导致上一轮路径继续存在。

修复后每次提交都会显式发送 `signal_path`；没有信号时发送空字符串，覆盖并清除旧状态。明确诊断请求缺少信号时，页面返回上传提示。

### 3.3 剩余寿命问题先进入诊断审核

“还能运行多少天”中的“运行”曾被识别为“运行诊断”，并且旧 Demo 图先判断诊断、后判断高风险边界。

修复包括：

- 不再把普通“运行”作为诊断动作；
- 剩余寿命、远程控制和不支持精度等安全策略优先于诊断工具路由；
- 增加“有信号时安全策略仍必须抢占诊断”的图级回归测试。

## 4. 验证边界

### 4.1 AutoDL Full Agentic 页面复验

规划热修复增加了两项通用约束：模型最后一条规划指令再次强制只输出完整 JSON；诊断或信号检查工具误把 `signal_file` 写入 `depends_on` 时，系统将其作为已注入资源剥离并记录到 `removed_dependencies`，其他未知依赖仍然拒绝。

真实页面复验结果：

| 场景 | 结果 |
|---|---:|
| 外圈点蚀知识问题，默认样例信号已勾选 | 正常结构化证据回答，无规划降级，不进入 CNN 审核 |
| 明确诊断请求 | 首轮合法计划，进入审核；Approve 后执行真实 CNN，无规划降级 |
| 诊断审核隐私 | 只显示 `test_signal.npy`，不显示服务器绝对路径 |
| 真实 CNN 本次输出 | 滚动体故障，模型置信度60.87%；仅为工具输出，不代表准确率 |
| 精确剩余寿命 | 安全策略直接拒绝，不调用工具 |
| 两个指定问题连续3轮规划检查 | 6/6 无 `deterministic_fallback` |

热修复后的冻结自动回归：

| 数据集 | 自动合同 | 平均 / p50 / p95（秒） | 规划路径 |
|---|---:|---:|---|
| 13-turn Demo | 13/13 | 5.333 / 6.031 / 9.851 | 首轮7、重试2、确定性fallback 2、无规划2 |
| 64-turn正式集 | 63/64 | 4.569 / 5.442 / 8.954 | 首轮31、重试14、确定性fallback 7、无规划12 |

正式集唯一失败位于 `diagnosis` 分组：引用有效率与 Grounded Guard 均为37/38。失败明细未继续定位，因此当前热修复代码不能沿用此前 Fix 3 的64/64口径。
