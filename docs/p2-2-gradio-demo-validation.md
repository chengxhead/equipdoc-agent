## 3. 验证过程中发现并修复的问题

### 3.1 知识问题被样例信号误导为诊断

旧 Demo 策略把“轴承”“故障”“状态”等领域词本身当作诊断意图。页面默认携带样例信号时，纯知识问题会错误进入 CNN 审核。

修复后只在以下情况进入诊断：

- 明确指向当前、上传或这段信号的诊断、分析、判断、分类请求；
- 明确命令式要求执行诊断；
- 明确要求输出故障类型、概率、置信度或诊断结论。

“为什么、什么、哪些、通常、机理、区别、表现”等自包含知识问题不会因为页面携带样例信号而改变路由。

### 3.2 取消样例后仍继承上一轮信号

Gradio 在同一 `thread_id` 下保留 LangGraph 状态。旧提交在没有新信号时省略 `signal_path` 字段，导致上一轮路径继续存在。

修复后每次提交都会显式发送 `signal_path`；没有信号时发送空字符串，覆盖并清除旧状态。明确诊断请求缺少信号时，页面返回上传提示。

### 3.3 剩余寿命问题先进入诊断审核

“还能运行多少天”中的“运行”曾被识别为“运行诊断”，并且旧 Demo 图先判断诊断、后判断高风险边界。

修复包括：

- 不再把普通“运行”作为诊断动作；
- 剩余寿命、远程控制和不支持精度等安全策略优先于诊断工具路由；
- 增加“有信号时安全策略仍必须抢占诊断”的图级回归测试。

## 4. 验证边界

- 本记录验证的是公开、无模型 Demo 页面，不代表本地运行了 Qwen 或真实 CNN；
- Full P2.2 的规划、结构化证据回答、真实 CNN 工具链和延迟以 [`artifacts/p2_2/`](../artifacts/p2_2/README.md) 的 AutoDL 原始证据为准；
- 人工回答质量复核按照当前决定暂时跳过；
- `knowledge_qa` 的 6 秒目标暂不作为当前验收条件。
